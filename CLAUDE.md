# Project Fitness: notes for working on this repo

- Single-page web app: the app is index.html (HTML, CSS, JS). Big data lives in separate files loaded in the background: demos.js (animated move/exercise demos, exposes window.PFDEMO) and foods.js (restaurant menus + world dishes, window.PFFOODS). Both are in the sw.js CORE list. Hosted on GitHub Pages at https://rizjr.github.io/Project-Fitness/
- Every release: bump `APP_VERSION` in index.html (e.g. 2026-10-23-2). Installed apps compare it with the live copy and refresh themselves.
- If files cached for offline use change (sw.js CORE list), also bump `CACHE` in sw.js.
- Cloud: Supabase project URL + publishable key in index.html (`CLOUD_URL`, `CLOUD_KEY`). Never put a secret/service_role key in this repo.
- Database changes go in a new `supabase-update-N.sql` and are appended to `supabase-setup.sql`. The owner runs them in the Supabase SQL editor.
- Server code: `supabase/functions/reminders/index.ts` (phone reminders, runs every 15 min via pg_cron; also sends "rest over" pushes when pg_cron job pf-rest, every 10 s, finds a due row in rest_timers — see supabase-update-4.sql). The owner deploys it in the Supabase dashboard with "Verify JWT" off. It uses the service key Supabase injects; never put that key in this repo. Test logic locally with Deno (PF_TEST=1).
- Privacy notice: privacy.html. Update its date if what we store changes. Terms of use: terms.html (plain English, England and Wales law; linked from Settings › About, privacy and support pages). Both are in sw.js CORE and scripts/build-www.mjs.
- Pinned roadmap items: ROADMAP.md.
- iPhone App Store version: Capacitor wrapper (`package.json`, `capacitor.config.json`, `ios/`, iPhone only), built in the cloud by Codemagic (`codemagic.yaml`, workflow "iOS to TestFlight"). `npm run build` copies the web files into `www/` (list in `scripts/build-www.mjs`; add new web files there). In index.html, `NATIVE` is true inside the iPhone app: it uses the Haptics plugin and local notifications (rest-over, idle, daily reminders via `nativeDaily()`), skips the service worker, the self-update check and web push, and points outbound links at `WEB_URL`. Owner's step-by-step guide: APP-STORE.md.
- Coach-led sessions: the coach logs a client's session in the workout player (`S.draftWorkout.forClient`, saved as `csession` docs, never as the coach's own `workout`). Linked clients get it through the plans table as a `type:"coachlog"` row (id `log_<csession id>`, date in `on`, so the reminders function ignores it); `applyCoachLogs()` turns it into a workout in their app. Clients added on the coach's phone are `client` docs with `local:true` and can be moved into a linked client (`csMerge`). Reports include `lifts` (latest 3 sessions per exercise) so the coach sees last weights.
- Apple Health (iPhone only, opt-in in Settings › Apple Health): `@capgo/capacitor-health` (`Capacitor.Plugins.Health`) reads steps, sleep and weight and saves weight; the app's own `ios/App/App/PFWorkoutPlugin.swift` (`Capacitor.Plugins.PFWorkout`, registered in `MainViewController.swift`) saves workouts. Entitlement: `ios/App/App/App.entitlements`. JS: `hkConnect`, `hkPull` (on open and return to the app), `hkSaveWorkout`, `hkSaveWeight` (called from `save()` for body docs; imported weigh-ins carry `hkFrom` so they aren't written back).
- Watch data via Apple Health: `hkDays()` keeps a 30-day daily summary in the `hkdays` doc (sleep, rhr, hrMin, hrv); `recoveryFor(date)` scores it against the person's own last 14 days (needs 4 days) plus yesterday's training and the morning check-in; shown on Recover, Today and (via report `recovery`) to the coach. `hkWorkoutsHR()` adds `hr:{avg,max}` to recent workouts. Settings › Connect your watch (`setWatch`, `WATCH_STEPS`) is the per-device set-up guide.
- Live heart rate (iPhone): `@capacitor-community/bluetooth-le` (`NPlug("BluetoothLe")`, raw native calls: requestLEScan/stopLEScan/connect/startNotifications; the app draws its own monitor list (`hrScan`, `HRS`, `hrScanInner`: heart-rate service only, named devices only, closest first, 20 s; "show all nearby devices" = `hrAll`) instead of the plugin's requestDevice picker, which listed every device with overlapping labels; notification event key `notification|<id>|<service>|<char>`, value is a hex string). `HRL` holds the connection; `hrStart/hrStop/hrPaint` (updates `.hrlive/.hrzone/.hrdot` in place each beat). Recorded into `S.draftWorkout.hrLog` ([secs, bpm] every 5 s); on save `hrSummary()` sets `w.hr` (avg, max, zone seconds) and it travels with coach-logged sessions. Zones: `hrMaxFor()` = 208 − 0.7 × age (profile dob/hrAge, client `age` from their report or entered by the coach). Monitor remembered per person in localStorage `pf-hrdev:<profile>:<me|clientId>`.
- Swaps: `SWAP_FAM` (index.html) groups variations of a movement with rough weight ratios (dumbbells per hand, 0 = bodyweight, null = no conversion). In the player, Change › "Swap for a variation" (`swapPanel`, `wpSwap`) converts the planned kg or uses their own history, keeps the plan in `ex.planSets` until save, saves `swapFrom` on the exercise, remembers the choice in `settings.swaps`; the coach report carries `from` so Planned vs done matches swaps.
- Rest-end sound: `restSound()` plays `bell()` (synthesised boxing bell, default) or `beep()` per `settings.rest.tone`; the iPhone rest-over notification uses `ios/App/App/bell.wav` (same recipe). No latency: `restArm()` books the sound on the AudioContext clock when rest starts or changes (`restDisarm()` on skip/stop/background), `restTimers()` fires an exact setTimeout at the end (and wakes audio 1.5 s before), `restFire()` vibrates first (Haptics HEAVY impact, then vibrate).
- Training reminder (`reminders.gym`: on, time, days): kind rotating message (`GYM_LINES`/`gymMsg`, duplicated in the reminders function) on planned days or chosen/usual training days, skipped if already trained. Native: `nativeDaily()`; web push: reminders function `decide()` (owner must redeploy after changes). Turning it on mirrors into `reminders.plan` so an older server still sends something.
- Exercise library: `EX_LIB` (gym, by muscle group) and `EX_MORE` (bodyweight/functional/calisthenics), ~350 exercises; every name has an exact demo pattern in demos.js `EX_PAT` (avoid relying on `EX_GUESS`, it mis-guesses e.g. "machine"). Search: `exSearch`/`exScore` (all words in any order, `EX_SYN` shorthand like db/rdl/ohp as whole phrases, plurals, muscle group 2 pts, muscles 1 pt, `EX_CLASSIC` boost). Player actions: `wpSwap` = pick from search (wpSetExercise), `wpVar` = swap for a variation.
- WHOOP-style watch health: `hkDays()` reads Apple Health into the `hkdays` doc (`v:2`, `full` = date of last 30-day re-read, else last 4 days): per date rhr, hrMin, steps (queryAggregated; the plugin only aggregates steps/heartRate/restingHeartRate), hrv, resp, spo2 (fraction ×100; resp/spo2 use overnight readings, else that day's, since Garmin-bridge apps like Vitals Sync/HRV Sync may stamp daily values at midday), temp, vo2 (readSamples, averaged in JS), sleep + `sl` {d,r,l,a mins, b/w = bed/wake minutes from that date's midnight, st = has stages} via `sleepNights()` (one source per night, prefers staged; nights keyed by wake date), strain + z. Strain: `dayStrain()` = Edwards TRIMP from zone seconds (`hrZoneSecs`, 10-min gap cap) + 0.1/min light movement (40–50% max) + estimate for sessions without HR (`trimpEst`), live-session zones replace Health samples in their window; `strainOf(t)=21(1−e^(−t/180))`. Backfills ≤4 older days per pull (`sx` = tried, no data). `HK_READ`/`HK_V=3`, `hkAuth()` retries without wrist temperature (iOS 15).
- Shared helpers work on any days map (own `hkdays` or a client's `watch.days`): `normRange` (30-day median ± max(min band, 1.5×MAD)), `healthMonitor`/`HM`, `sleepNeed`, `sleepConsistency`, `strainTarget`. Client UI: `recoveryCard()` on Recover (rings, sleep, health monitor, last 7 days), `recoveryRow()` on Today.
- Coach sharing: `profile.shareWatch` (switch in Settings › Apple Health, one-time prompt `swYes/swNo` on Recover). Report `watch` = `watchReport()` {days (+rec), sessions, maxHR}; `recovery` is also gated by it. Coach: `watchPanel` on the client page, `healthCheckPage` (state `S.hc={id,week}`, actions hcOpen/hcClose/hcWeek/hcShare, per-week notes in client doc `hcNotes`), `hcPoints` = automatic talking points (trends only, never a diagnosis; GP wording for out-of-range breathing/temperature/oxygen). Client docs keep `watch` and `hcNotes` when reports arrive.
- Health connection status: `hkStatus(full)` (connected panel on Settings › Apple Health, watch guide, Recover when no data yet), `hkReceived()` (what's arriving per measure), `S.hkBusy` while connecting, `S.hkSyncing`/`hkLast()` for sync state. Freshness: `hkFresh()` reads the newest heart-rate sample (not steps: the iPhone records those itself) → Live ≤20 min / Recent ≤3 h / Waiting, with a hint per source (Garmin Connect must be open); painted in place via `.hkfresh`/`.hkftag` (`hkFreshPaint`). Re-checked every 60 s on those screens and on return to the app; if newer than the last sync (`S.hkSeen`) it syncs at once.
- Workout heart rate: `hrNow()` = Bluetooth monitor if connected, else (own sessions only) the latest Apple Health heart rate if ≤2 min old (`HKL`, polled every 15 s by `hkLiveTick` while the player is open). `hrPaint` uses it for the chip, rest line and sheet.
- Connecting: `hkOn()` = local flag `pf-hk:<profile>` ("1"/"0", set by hkConnect/hkOff) else synced `settings.health.on`, so a settings copy synced from another device can't switch it off. `hkConnect` saves as soon as Health access is granted; PFWorkout (save workouts) permission has a timeout and is non-fatal; `hkAuth` falls back to `HK_BASE` types; errors shown on Settings › Apple Health via `S.hkErr`.
- Tests: `tests/` holds the Playwright browser tests (fake iPhone/Apple Health and fake Supabase in `mocksb.js`); `node tests/run.mjs [names]` from the repo root serves the app on :8767 and writes logs/screenshots to `tests/shots/` (ignored). Some older tests target earlier screens; check whether the app or the test is out of date before changing the app. A weekly scheduled run tests the app, puts small fixes on a `weekly-fixes-<date>` branch with a PR, squash-merges its own PR only when every previously passing test still passes (owner's request; never pushes straight to main), and reports to the owner.
- Daily coaching call: `coachCall(days,D,{check,rec})` → {k: push|train|easy|rest, title, line, why[], todo[], basis hrv|basic, target strain}. HRV rule = 7-day rolling mean of ln HRV vs baseline (days 8–30 back, ≥10 values) mean ± 0.5 SD (`hrvTrend`, Plews / Javaloyes 2018); also RHR 3-day vs normal, breathing/temperature above normal (illness signs), SpO2 low 2 of 3 nights, sleep vs need/debt, strain 7d vs 28d ratio (soft hint), check-in. `myCoachCall(D)` for the user; `coachCallHtml` on Recover (replaces the band advice), `recoveryRow` on Today, `coachBanner` before the warm-up in the player (client's call when training a client), `watchPanel` + `hcCalls` (daily calls row) + HRV talking points on the coach side. `hrvTrendSvg` = nightly dots, 7-day line, usual range. Wording: coaching, never a diagnosis; GP/NHS 111 only for persistent illness signs or SpO2 <90. Evidence guide for the owner: Claude Doc "Coaching with HRV, breathing rate and blood oxygen". Test: tests/tcoachcall.mjs.
- Bedtime reminder (`reminders.sleep`: on, goal keep|improve|early|travel, wake "" = from data, wind mins, from/since for improve, early {date,wake}, travel {date,diff h}): `sleepBase()` (usual wake per weekday/weekend, usual bedtime, sleep efficiency from the last 21 nights), `sleepNight(D)` (lights out = wake − need ÷ efficiency; keep goal capped at 1 h earlier than usual; improve = 15 min earlier every 3 days; early = 8 h for the set wake-up, half shift the night before; travel = 30 min a night towards the destination for up to 4 nights, Harvard Health), `sleepTip(D)` (late hard session, low HRV → alcohol, sleep debt, consistency, caffeine rotation), `sleepPanel()` in Settings › Reminders, a "Tonight" line on Recover's sleep card. iPhone: N_ID.sleep 1400–1406 in `nativeDaily`; web open: `scheduleReminders`; web push: `sleepSync()` saves the next 7 wind-down times in `reminders.sleep.plan` (date → {at,title,body}) and the reminders function's `decide()` sends them (owner must redeploy it). Test: tests/tsleep.mjs.
